# PR-15 capture reliability and quality

Baseline and device captures use shared readiness, smart scroll and screenshot validation. Readiness observes readyState, fonts, visible images, DOM size and document size; it does not wait for networkidle or infinite animation completion. Scroll is limited to 16 steps and 16000 CSS px, restores original position, and never clicks controls. Attempts share an elapsed-time budget (baseline configured screenshot timeout, device 18000 ms); at most two screenshot attempts in the same context, no new navigation. Existing browser/proxy guards and job hard deadlines remain in force. Synchronous browser evaluate and PNG decode cannot be preempted by the cooperative deadline; hard task limit still applies.

PNG verification checks decode, dimensions and uniform rendered RGB; fully white, fully uniform, empty, corrupt and over-budget images are rejected. Sparse near-white images are warnings because minimal valid pages exist. Warnings also flag overflow, unsettled readiness and bounded scroll. They are not claims of complete evidence. Only validated images are written atomically and registered. Baseline retains full-page limits, devices retain explicit viewport fallback and CSS scale. Old manifests have unknown quality and remain readable. New baseline quality appears in capture_quality and artifacts; device entries include quality. Failures include attempt codes and are excluded from screenshot registries and kit file lists. Existing manifest/hash checks remain.

Limitations: heuristics cannot prove visual completeness, hydration or semantic correctness; scroll-triggered content may disappear when returning to top; scroll can trigger normal site scripts/requests. No arbitrary click or new access mode. Explicit interaction-state capture polls readiness for at most 5 seconds after navigation, then closes its existing offline network gate before the single declared action. Screenshot timeout is 8 seconds; no repeated action. Invalid PNGs rejected; blocked requests and unsettled readiness are explicit warnings on captured states. No DB migration. Existing historical files are not reclassified.

Verification gate: run python -m pip install -e '.[dev,server,capture]', python -m playwright install chromium, python -m pytest -v; frontend npm ci, npm run test, npm run build; disposable PostgreSQL integration, Docker GUI and selected ZIP checks.
